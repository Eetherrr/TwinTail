# 安全与依赖升级策略

P6 Linux本地候选完成。此策略用于MIT授权的GitHub0.1.0发行准备与候选审查，不宣称已提供安全维护期限、签名市场或自动更新渠道。

## 许可与来源

用户已决定项目使用MIT，并授权GitHub公开仓库和0.1.0发行准备；根LICENSE与Cargo许可元数据由lead同步。发行前核对制品包含项目许可及实际需要的第三方声明，依赖元数据不能代替逐项再分发义务核对。候选工具默认不自动上传或cargo publish；公开推送与Release是否完成须以实际操作记录为准。

## 依赖升级

保留Cargo.lock和前端package-lock.json，使用--locked与npm ci。分别审查直接和传递依赖、build.rs/安装脚本、许可证、网络访问与新增能力，记录变更来源。依赖审计报告0漏洞只代表当时数据库和检测范围，不证明没有漏洞。

升级后按影响运行fmt、全目标严格Clippy、默认测试、rustdoc、Schema/OpenAPI漂移、静态资源重建与前端交互；生命周期/存储变化还运行显式CLI、备份恢复与合同/soak。工具链或MSRV变化单独说明，不把在高版本构建成功当作旧MSRV兼容。对目标平台分别记录运行与编译证据。

wire可选字段扩展与配置/业务数据升级分别审查，未知必需能力或主版本不兼容明确拒绝。依赖提供者/消费者范围同步更新，不靠重试修复协议不兼容。安全修复仍须保留版本和迁移路径，不能静默覆盖已安装版本目录。

## 凭据与故障

秘密只使用环境引用与受控注入，不进入制品、备份示例、CI输出或浏览器响应。writeOnly字段的旧字面量配置由Web拒绝，应CLI迁移为引用；不要回写脱敏占位符。适配器禁用依赖TRACE/debug以免Bearer握手泄漏，升级日志库或WS库时必须重测该边界。

反向监听已按数字 loopback、精确路径/身份/鉴权头、单活动连接、握手期限与有界队列实现，并经本地 mock/SDK 回归核对；真实 SnowLuma reverse 尚未验证。当前不对公网暴露管理面，不把loopback与独立进程当作隔离同用户恶意代码的安全边界。包摘要不是签名，备份摘要不是加密；私有备份仍可能包含敏感业务数据。

本轮实际工具与审查范围见[依赖与安全审查](dependency-audit.md)，不将audit无告警等同无漏洞或项目发行授权。
