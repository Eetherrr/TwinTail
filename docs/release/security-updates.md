# 安装来源、凭据与依赖升级

本页说明部署时应保护什么、维护者升级依赖时要核对什么。TwinTail 已采用 MIT 并公开 v0.1.0；这里不承诺安全维护期限、签名市场或自动更新渠道。

## 普通使用者先做这四件事

1. 从已确认的来源取得匹配平台的包，比较发布摘要。SHA256 就像文件指纹，能发现内容变化，不证明发行者身份。
2. 只运行受信任插件。插件是当前用户权限下的独立程序，不是系统沙箱，宿主权限校验只约束经宿主发起的调用。
3. 把 OneBot token 和 Web 管理 token 分开保存。配置里写环境变量引用 `{"$secret":"ENV_NAME"}`，实际变量由启动宿主的私有环境提供。
4. 升级前停机备份。备份摘要不是加密，备份可能保留真实业务数据和旧字面量秘密，应放在受保护位置。

遇到泄露或可疑问题，按根目录 [SECURITY.md](../../SECURITY.md) 的说明准备脱敏证据和报告，不把真实账号、token 或消息正文贴到公开日志。

## 许可与来源

项目已使用 MIT 公开源码并发布 v0.1.0，根 LICENSE 与 Cargo 许可元数据已就绪。发行前核对制品包含项目许可及实际需要的第三方声明，依赖元数据不能代替逐项再分发义务核对。底层打包工具不自动上传或执行 cargo publish；新构建包的公开推送与 Release 状态以实际记录为准。

## 维护者：依赖升级前后怎么做

“依赖”包括程序直接使用的库，以及库再使用的其他库。锁文件固定本次使用的精确版本；扫描器只对已知数据库条目给出匹配，不是完整安全证明。

保留Cargo.lock和前端package-lock.json，使用--locked与npm ci。分别审查直接和传递依赖、build.rs/安装脚本、许可证、网络访问与新增能力，记录变更来源。依赖审计报告0漏洞只代表当时数据库和检测范围，不证明没有漏洞。

升级后按影响运行fmt、全目标严格Clippy、默认测试、rustdoc、Schema/OpenAPI漂移、静态资源重建与前端交互；生命周期/存储变化还运行显式CLI、备份恢复与合同/soak。工具链或MSRV变化单独说明，不把在高版本构建成功当作旧MSRV兼容。对目标平台分别记录运行与编译证据。

wire可选字段扩展与配置/业务数据升级分别审查，未知必需能力或主版本不兼容明确拒绝。依赖提供者/消费者范围同步更新，不靠重试修复协议不兼容。安全修复仍须保留版本和迁移路径，不能静默覆盖已安装版本目录。

## 凭据与故障

秘密只使用环境引用与受控注入，不进入制品、备份示例、CI输出或浏览器响应。writeOnly字段的旧字面量配置由Web拒绝，应CLI迁移为引用；不要回写脱敏占位符。适配器禁用依赖TRACE/debug以免Bearer握手泄漏，升级日志库或WS库时必须重测该边界。

反向监听已按数字 loopback、精确路径/身份/鉴权头、单活动连接、握手期限与有界队列实现，并经本地 mock/SDK 回归核对；真实 SnowLuma reverse 尚未验证。当前不对公网暴露管理面，不把loopback与独立进程当作隔离同用户恶意代码的安全边界。包摘要不是签名，备份摘要不是加密；私有备份仍可能包含敏感业务数据。

本轮实际工具与审查范围见[依赖与安全审查](dependency-audit.md)，不将audit无告警等同无漏洞或项目发行授权。


## 怎样算完成，失败时怎样处理

- 扫描有命中：保留原报告，核对锁定版本、依赖链、advisory 适用范围与实际调用，不仅为清零而跨大版本升级。
- 构建或回归失败：停止该次分发，修正后重新运行受影响平台检查，保留旧可用版本和恢复点。
- Web 拒绝秘密配置：先用本机 CLI 迁移完整 values 为环境引用，再回 Web 操作，不把占位符当成真实 token。
- 升级通过：记录源码提交、依赖/锁文件变更、执行命令、平台结果、迁移和回退方法。审计通过仍不扩大真实 SnowLuma 的验证范围。
