# ADR 0008：显式彻底移除插件

- 状态：已实现（Linux 本地验收；Windows 新路径待原生回归）
- 日期：2026-11-08

## 背景

版本包位于 `packages/<id>/<version>/`，配置与业务数据位于 `data/plugins/<id>/`。原有卸载只删除指定未启用版本，默认保留配置与数据，避免重装/升级误删持久状态。目录分离需要明确的完整清理契约，而不是改变普通卸载语义。

## 决策

增加独立管理写方法 `plugins.purge`，参数为 `{id, confirm_id}`，确认字符串必须与目标 ID 完全一致。CLI 与 WebUI 都显式区分“卸载此版本”和“彻底移除插件”。WebUI 要求输入 ID，并说明删除所有版本、配置和业务数据，启用中的插件须先停用，不自动级联删除依赖。

宿主拒绝仍被启用计划、运行规格或启用中的强依赖消费者引用的目标；调用方先停用并等待操作完成。未启用版本包的依赖声明不阻止移除，之后启用时重新校验依赖。沿用现有依赖检查与直接子进程回收，不在 purge 内拼接隐式生命周期事务。彻底移除只处理统一安装根下目标 ID 的全部版本及私有数据根下目标 ID 的目录；不删除全局操作审计、环境秘密源、其他插件或外部资源。

删除由宿主管理执行，不依赖插件自身回调。路径必须校验目标身份、祖先和目录内容，拒绝符号链接/重解析点等越界路径；资源删除沿用 OS 锁和管理 actor 的串行规则。只移除版本的原有卸载保持兼容。

## 失败与重试

该操作是多目录破坏性删除，不是跨文件系统原子事务。先进行可行的预检，操作记录暴露阶段和终态；中途权限/IO 失败须返回错误，已经完成的删除不回滚。目标缺失应允许重试继续清理残余目录。配置 CAS 与移除共用 namespace 父目录下 `.config-locks/<SHA256(ID basename)>.lock` 稳定外部门闩（任意 ConfigStore 目录同样按 basename 计算，退役名称 `.purge-ID` 归一到原 ID）；锁为宿主元数据，永久保留且不含配置内容。沿用内部 `config.lock` 兼容既有 CAS 互斥，外部门闩取得后可在退役前释放内部句柄，避免 Windows 打开子文件句柄阻止父目录 rename。数据命名空间在持续持有外部门闩时先退役到同级内部 `.purge-ID` 目录，再删除；中断遗留的退役目录也在下一次同 ID 重试时预检并清理，避免在原路径逐文件删除锁而允许并发 CAS 重建。调用方检查操作结果而非仅检查接纳 ACK。重试可能需要先修复文件系统权限或危险链接，禁止偷偷跟随链接删除目标。运行中的 purge 遇到宿主正常关闭时必须等待已启动的删除工作收束后再记录实际终态，避免 detached blocking worker 在终态后继续推进删除；进程被强制终止仍可能留下待重试的部分状态。

## 边界

受信任插件当前以宿主用户身份运行，可能写入目录外文件或产生外部服务资源；本功能只承诺宿主管理目录的清理，不声明文件系统沙箱或全系统零残留。业务数据删除不可恢复，执行前应按需冷备份。

## 验收

覆盖显式确认、启用/依赖冲突、多个版本与配置数据删除、其他插件隔离、危险路径拒绝、幂等重试和操作查询；WebUI 覆盖输入 ID 确认、权限及启用状态限制；HTTP 合同与文档同步。
