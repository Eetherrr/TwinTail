# 冷状态备份与新根恢复

`state.py` 使用 Python 3.11+ 标准库，支持有 AF_UNIX、`flock` 与目录 `fsync` 的 Unix 文件系统。Linux 本地测试通过；Windows named pipe、DACL 与目标运行状态无法由该工具可靠核查，因此在 Windows 明确拒绝运行。其他 Unix 和网络文件系统未验证。它处理数据根，不备份安装包、可执行文件、进程、远端 OneBot 状态或外部环境变量来源。

## 命令与停机流程

先正常停止宿主并确认它监管的插件已经退出，暂停自动重启服务、定时任务和直接写业务目录的程序。保持数据根仅由可信的当前用户操作。正常退出会删除宿主自己的管理端点。

```sh
python3 tools/state/state.py snapshot /srv/twintail/data /srv/twintail-backups/before-p6
python3 tools/state/state.py verify /srv/twintail-backups/before-p6
python3 tools/state/state.py restore /srv/twintail-backups/before-p6 /srv/twintail/data-p6
```

备份和恢复目标的父目录须已存在，目标必须不存在或为当前用户拥有的空 0700 目录。源和目标不得嵌套；禁止覆盖现有数据。恢复完成后不会切换服务、修改原根或启动宿主。成功只输出文件数、配置数和 desired/applied 不一致数量，不输出配置实例、秘密或路径。失败退出码为 2，错误使用固定原因。

停止检查以当前 Unix 宿主的实际启动互斥机制为准：工具独占绑定 `DATA/management.sock` 并持有至操作结束；宿主在启动插件前绑定同名端点且拒绝任何已有端点。工具不监听或模拟管理接口。发现任何已有端点都拒绝操作，包括无人监听的崩溃残留；连接失败不被当作停机证明。根目录出现 `run.lock`、`host.lock` 或 `host.run.lock` 也一律拒绝。工具不根据 PID、时间戳或锁文件年龄认定安全，不自动删除已有端点或运行锁。

若残留端点阻止操作，先通过服务管理器及本机进程检查确认旧宿主和全部插件均已退出，核对该端点确实属于该数据根，再由运维手工处理；工具没有 `--force` 或绕过选项。工具只清理自己创建且 inode 仍匹配的占位端点。现有宿主退出时也只删除自己持有的端点；未来宿主若改为自动删除未知端点，必须先重新审查该工具的互斥合同。

`plugins/<id>/config.lock` 的 OS 锁须可排他取得，锁文件不会进入备份；恢复后由 core 重建。其他业务文件即使同名 `config.lock` 也保留。复制前后比较源目录库存与文件元数据，读取前后检查文件身份和变化。占位端点阻止协作宿主启动，配置锁阻止已有配置事务；它不能隔离同用户恶意进程、已脱离宿主的插件或外部业务写入者。停机与暂停其他写入者仍是必要条件。

## 数据格式、权限与验证范围

备份目录包含 `manifest.json` 和 `tree/`；前者记录版本 1 的文件库存、长度及 SHA256。SHA256 检测意外损坏，不认证备份来源，不能证明恶意修改后的 manifest 可信。只接受可信离线介质和当前用户拥有的私有根。

原文件字节被保留，输出目录统一为 0700、文件统一为 0600，不继承更宽权限或可执行位。安装根不在本工具范围，因此不会把此权限策略应用到插件可执行文件。UID/GID、ACL、xattr、稀疏性和时间戳不被归档；权限保护范围是当前用户。`verify` 拒绝被放宽的备份权限。备份 manifest 也可能包含私密文件名，应和业务数据一样保护。

环境变量从未被查询、展开或写入备份。原始 `{"$secret":"ENV_NAME"}` 引用按原字节保存，环境实际值及外部凭据提供文件须由运维单独配置。**根内已有的明文秘密、业务内容和其他私密文件仍会被备份**，不会猜测和脱敏，也不会用占位符改写数据。请把环境变量来源放在数据根之外，并保护备份介质；本工具不提供加密或密钥托管。

拒绝符号链接（包括路径祖先）、硬链接、非当前用户文件、socket、FIFO、设备及其他特殊文件；目标项以 `O_EXCL` 创建，常规文件使用 `O_NOFOLLOW` 打开。仅使用本地可信私有目录，不把路径检查宣称为针对恶意同用户修改的文件系统沙箱。文件名中的反斜线、冒号和路径穿越被拒绝；备份中的重复路径、库存外文件或缺项也被拒绝。

固定限额为 10,000 个树项、目录深度 32、单文件 64 MiB、总文件内容 1 GiB、manifest 4 MiB。插件配置 TOML 最大 2 MiB，JSON values 最大 1 MiB，结构深度 32、节点 65,536。配置只核查 envelope 的 `config_version`/`revision`/`values`、JSON 兼容值、秘密引用及 applied revision 不超前；脱敏占位符被拒绝。合法 desired/applied 不一致原样保留并计数，不擅自确认 applied 或增加 revision。

`verify` 不执行 JSON Schema、不解析秘密、不运行插件，也不验证 host.toml、包摘要、平台、依赖、外部连接或业务数据语义。它不是通用 schema 迁移器；结构检查通过不等于可以上线。恢复前和读取待复制内容时均核查完整性。常规失败回收本次已创建条目；若发生进程崩溃、磁盘错误或外部并发修改，可能留下私有部分目录或占位 socket，应保留并人工检查，换另一个空目标重试。绝不把半成品作为成功结果。原数据根和备份不被 restore 修改。

## P4 正向配置升级到 P6

P6 适配器保持 `config_version = 1`，旧配置省略 `transport` 时仍解释为 `forward_ws`。真实兼容路径是保留旧 `url`、`self_id`、`access_token` 引用和所有现有参数，备份并恢复到新数据根；无需增加字段、重写 TOML、提升配置版本或修改 desired/applied revision。本工具测试用实际 P4 envelope 证明其字节和秘密引用经过 snapshot/verify/restore 后保留。适配器自身另有旧配置默认行为测试，本工具不代替它。

可以在新根离线编辑配置前先再做一份冷备份。显式 `transport = "forward_ws"` 与省略字段表达同一传输模式，但编辑仍须遵守宿主 CAS 与配置事务；本工具不会替你修改版本或 applied 状态。

`reverse_ws` 属于新的部署选择：需要人工选择监听地址、路径、凭据和远端配置，并排他重启。默认监听为数字 loopback `127.0.0.1:17281`，路径 `/onebot/v11`，reverse 模式不使用正向 URL。工具不会把旧 URL 猜测成监听地址，也不会自动切换正反向模式。以 P6 适配器指南及实际 schema 为字段合同。

恢复到新根后，保留原安装包根并先执行只读包/计划检查：

```sh
twintail-host --validate --data-dir /srv/twintail/data-p6 --install-dir /srv/twintail/packages-p6
```

`--validate` 只检查宿主计划及包兼容，不构成配置秘密解析、插件 readiness 或外部 OneBot 的运行验证。核对包版本/摘要、目标平台及 config_version，注入外部环境来源，再使用目标宿主对新根受控启动并检查配置 desired/applied、生命周期和连接状态。新根就绪前保持原服务停止，避免两个根同时连接或产生业务副作用。不要把历史 applied marker 当作新进程已应用的证明，应由宿主启动确认实际应用。

## 回退

上线前固定旧宿主版本、旧安装包根、环境来源和完整冷备份。升级失败时，先停止新根宿主及插件，保留新根供诊断；把旧冷备份恢复到**另一个不存在或空的私有根**，以旧宿主和旧安装包执行离线检查，再受控启动。不要把旧备份覆盖到新根或仍在线的原根。

回退整棵状态会回到备份时点；升级后新增的业务写入、远端消息及外部副作用不会自动合并或撤销。涉及业务数据格式变化时须采用插件明确定义的迁移/回退合同，先冷备份，必要时由业务方人工处理。配置回退不代表通用业务数据回滚。

## 测试

```sh
python3 -m unittest discover -s tools/state -p 'test_*.py' -v
```

测试使用临时私有目录和脱敏夹具，覆盖实际端点互斥、active/stale 拒绝、配置 OS 锁、权限、校验和、库存、路径/链接、限额、失败回收及 P4 配置引用与修订不一致的往返保留。Python 工具不会触发真实 QQ 操作。
